День 6 — Надёжность, guardrails и обработка ошибок

🎯 Цель дня
Сделать LLM pipeline устойчивым к типичным сбоям и плохим ответам модели.

📋 Задачи
1. 🔁 Добавить retry при временных ошибках API
2. 🛡️ Добавить fallback prompt или fallback режим при плохом ответе
3. ⚠️ Обработать кейсы:
   - пустой ответ
   - невалидный JSON
   - слишком длинный ответ
   - ошибка API
4. 📝 Добавить logging ключевых этапов и ошибок
5. 📏 Ввести базовые ограничения на формат и длину ответа
6. 🧪 Специально проверить минимум 3 негативных сценария

Пример негативных сценариев
- модель вернула текст вместо JSON
- часть ключей отсутствует
- API временно недоступно

🎉 Критерии успеха
- ✅ Программа не падает от типичных ошибок модели
- ✅ Есть retry или fallback логика
- ✅ Ошибки логируются и читаемы
- ✅ Минимум 3 проблемных сценария обработаны корректно
- ✅ Пайплайн остаётся usable даже при частичных сбоях
